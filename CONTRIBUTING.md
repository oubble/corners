# Contributing

## Setup

```sh
pnpm install
pnpm exec playwright install      # Chromium, Firefox and WebKit for the browser suite
pnpm dev                          # the lab at http://localhost:4174/capsule/
```

## Layout

```
src/
├─ geometry.ts     pure outline math, no DOM
├─ core.ts         runtime: mount · unmount · observe · diagnostics
└─ index.ts        auto entry: observe(document) on import
test/
├─ unit/           geometry properties (Vitest, Node)
├─ browser/        runtime behaviour (Playwright: Chromium, Firefox, WebKit)
└─ fixtures/       pages the browser suite drives, CSP-clean
demo/              the lab, deployed to lab.oubble.com/capsule
docs/              README figures, generated by `pnpm figures`
scripts/           figures, lab assembly, local server
```

## Before a pull request

`pnpm verify` runs everything CI runs: Biome, TypeScript, unit tests, build,
package lint (publint and Are The Types Wrong), size budget and the browser
suite. A pull request should keep it green.

Changes to the outline are held to a higher bar. The calibration constants in
`src/geometry.ts` come from a fit against a native iOS capsule; a change needs a
measured comparison against that reference, and the inline snapshot in
`test/unit/geometry.test.ts` changes in the same commit.

## Commits

Small, focused commits in the imperative mood: `Fix refit after remount`, not
`fixed stuff`. Anything users can notice goes in `CHANGELOG.md` under
`Unreleased`.

## Releasing

Versions follow [Semantic Versioning](https://semver.org): a fix is a patch, a
new option is a minor, anything that breaks existing markup or imports is a
major.

1. Move the `Unreleased` notes in `CHANGELOG.md` under the new version and date.
2. `npm version <patch|minor|major>` commits the bump and creates the tag.
3. `git push --follow-tags`. The `release` workflow verifies the tag against
   `package.json`, runs the full suite and publishes with provenance.

The very first version has to be published by hand, because npm only accepts
trusted publishing for a package that already exists:

```sh
npm login
npm publish --provenance=false
```

Then, on npmjs.com, open the package settings, add GitHub Actions as a trusted
publisher (repository `oubble/capsule`, workflow `release.yml`, environment
`npm`) and from there on every release goes through the workflow.
